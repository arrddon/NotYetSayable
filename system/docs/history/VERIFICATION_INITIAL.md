# 초기 구현 검증 기록

2026-09-13 로컬 환경에서 확인했습니다.

## 자동 검증

`npm.cmd test`: 11개 통과. 마이그레이션을 실제 PGlite SQL 엔진에서 실행합니다.

- A/B 독립 진행과 네 응답 없는 지도 확정 거부
- 동일 요청 재전송의 멱등성, 다른 요청 ID의 이중 Confirm 거부
- 서버 카운트다운, 별도 A/B 작업과 결과
- A 초기화 후 과거 작업·QR·브라우저 접근 차단, B 유지
- 재답변 덮어쓰기 및 이전 시도의 늦은 결과 거부
- 처리 실패, 운영자 복구, 시간 초과, 같은 질문 재시도
- 타 참가자 조회/변경, 운영자·worker RPC, 직접 SQL 쓰기 거부
- 초기화 이전 세대 응답의 RLS 격리
- QR 브라우저 바인딩, 답변을 유지하는 링크 재발급
- 세션 생성 멱등성, 작업 lease와 결과 형식 검증
- 디스크 DB 재시작 후 상태·요청 영수증 복원

`npm.cmd run build`: TypeScript 검사 및 Vite 정적 빌드 통과.

## 브라우저 확인

Codex 내장 브라우저에서 운영자 데모 로그인, 세션/QR 생성, A QR 입장, 동의/안내, Q1–Q4 제출과 결과 표시, 지도 클릭/확정, 완료 후 새로고침을 확인했습니다. Q1 제출 직후 새로고침에서도 서버 카운트다운을 복원했습니다. 이전 응답 조회에서 브라우저 뒤로가기를 눌렀을 때 진행 상태가 바뀌지 않고 현재 단계로 돌아오는 것을 확인했습니다. A가 Q2에 도달한 동안 B는 동의 단계에 머물렀습니다.

## 추가 확인이 필요한 환경

실제 Supabase 프로젝트의 Auth·Data API·Realtime, 서로 다른 휴대폰, 실제 인터넷 단절 후 복구, TD 카메라·OCR은 아직 검증하지 않았습니다. PGlite의 단일 연결 테스트는 클라우드 PostgreSQL의 실제 다중 연결 lock 경합을 대체하지 않습니다.
