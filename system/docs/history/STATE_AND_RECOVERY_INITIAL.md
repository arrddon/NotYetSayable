# 상태와 복구 규칙

## 상태의 주인

참가자 화면은 상태를 소유하지 않습니다. `nys_snapshot`으로 최신 상태를 가져오고, Supabase Realtime 변경 알림을 받으면 다시 조회합니다. 1.5초 간격의 조회 및 탭 포커스/온라인 복귀 조회가 누락된 알림을 보완합니다. 데모는 같은 SQL 함수와 주기적 조회를 사용하며 Realtime은 사용하지 않습니다.

각 참가자는 `(id, generation, revision)`으로 구분합니다. A/B는 동일 session 안의 별도 행입니다. `generation`은 초기화마다 증가하고, `revision`은 상태 변경마다 증가합니다.

```text
consent → tutorial → question Q1 → Q2 → Q3 → Q4 → map → complete

question:
ready → countdown → processing → result → Continue
                       ↓
                     error → Try Again → countdown
```

## 제출과 덮어쓰기

- 모든 변경 요청에는 브라우저가 만든 UUID가 있습니다. 미확인 요청은 sessionStorage에 남고 **요청 다시 확인**으로 동일 UUID/인자를 재전송합니다.
- 서버는 참가자 행을 잠근 후 소유자·세대·revision을 확인합니다. 이미 처리된 동일 요청은 다시 실행하지 않습니다.
- Confirm 승인 시 3초 뒤 실행 가능한 job과 countdown 종료 시각을 같은 트랜잭션에서 저장합니다. 브라우저가 닫혀도 요청은 유지됩니다.
- 한 참가자에게 실행 중인 job은 최대 하나입니다. A/B에는 각각 하나씩 있을 수 있습니다.
- 과거 응답을 보는 동작은 DB를 변경하지 않습니다. **이 질문 다시 답하기**를 눌러 해당 질문으로 이동하고 Confirm을 눌러야 이전 응답을 새 시도로 대체합니다.
- Continue는 미완료 질문 중 가장 앞선 질문으로 이동합니다. 네 응답이 모두 있어야 지도 확정이 가능합니다.
- 현재는 종합 해석/아카이브 기능이 없습니다. 추가할 때 응답 변경으로 오래된 파생 결과를 무효화해야 합니다.

## 로컬 처리 계약

`nys_worker_claim`은 service-role만 호출할 수 있습니다. 실행 가능한 job을 한 번 가져오고 고유 lease를 발급합니다. `nys_worker_finish`는 job/lease/세대가 모두 현재 작업과 일치할 때만 결과를 반영합니다. 완료 요청 재전송은 중복 응답을 만들지 않습니다.

지금의 mock worker는 1.5초 대기 후 `[테스트]` 텍스트를 반환합니다. 네트워크 업로드 재시도용 디스크 스풀은 아직 없으며, 처리기 재시작으로 중단된 작업은 시간 초과/운영자 복구 후 Try Again을 눌러야 합니다.

실제 TD 브리지를 붙일 때 추가할 부분:

- job별 파일과 A/B별 캡처 경로
- TD의 캡처 완료 응답과 처리 스크립트 호출
- 원자적 파일 저장 및 업로드 재시도용 디스크 스풀
- 같은 job을 재수신했을 때 확인된 캡처 재사용
- 캡처 여부가 불확실하면 자동 재촬영 대신 Try Again
- 공유 카메라를 쓰면 카메라 접근만 직렬화

## 운영자 복구

| 상황 | 조치 |
|---|---|
| 처리 중 멈춤 | 해당 참가자의 **중단 후 재시도 허용** → 참가자가 Try Again |
| 처리기 응답 없음 | 로컬 프로세스 재시작, 필요하면 위 복구 사용 |
| 참가자가 새로 시작 | 해당 A 또는 B의 **초기화** → 새 QR 입장 |
| 휴대폰/브라우저 교체 | **입장 링크 재발급** → 새 브라우저로 입장. 기존 답변 유지 |
| Internet Error | 연결 복구 후 **연결 다시 확인**, 미확인 요청이 있으면 **요청 다시 확인** |
| 운영자 페이지 새로고침 | 기존 상태/같은 탭의 QR 복원 |
| 운영자 탭을 닫아 QR이 없어짐 | 상태는 DB에 남음. **입장 링크 재발급** 사용 |

시간 초과는 job 생성 후 90초입니다. worker가 실행 중이면 만료 작업을 error로 바꿉니다. worker 자체가 꺼져 있으면 운영자 화면에 마지막 연결 시각이 표시되고, 운영자 복구로 error로 전환할 수 있습니다. 새로 발급되는 job은 다시 3초 카운트다운을 거칩니다.

초기화는 이전 job을 취소하고 접근 토큰을 교체합니다. 이전 세대의 응답은 DB에 남지만 새 참가자는 읽을 수 없습니다. 데이터 보관/삭제 정책과 내보내기는 전시 적용 전에 별도로 확정합니다.

## 호환성

응답 JSON은 `raw_response`, `translated_response`, `keywords`, `trace`, `classification`을 유지합니다. 현재 mock 결과는 `classification: null`, `analysis_status: not_configured`를 사용하여 분석된 것처럼 보이지 않게 합니다.

아카이브 어댑터는 아직 구현하지 않았습니다. 다음 단계에서 Q1/Q2/Q3을 past/present/future로, Q3을 legacy `Q3-1`로 매핑하고 Q4를 별도 확장 필드로 보존합니다. A/B/세대마다 고유한 exported `session_id`를 부여하고 기존 legacy 파일에는 쓰지 않습니다.
